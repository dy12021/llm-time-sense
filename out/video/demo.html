大模型的时间感

告诉模型它上一轮每秒能生成多少 token —— 它到底能不能因此知道「自己要花多久」？

问题

模型不知道自己有多快

让它预估「这条回复要写多久」，结果全是喊数字：目标放大 10 倍，它写出来的时长几乎不变。

云端 API 上（450 轮 + 长程 148 次）
注入 TPS 无效
但原因不是「模型不会用速率」
真正的物理前提
速率要稳
云端同一台机器测出 2.39× 的波动
第一步 · 把尺子校准

换到本机：速率真的稳了

云端 API 请求间波动
2.39×
CV 0.920 · 后端路由到不同吞吐的轨道
本机稳态波动
1.15×
CV 0.038 · 12 次采样
稳态速率
155
token / 秒（冷启动那次只有 100）
第二步 · 注入速率，看它动不动

速率这个数，真的进了它的判断

实验臂模型预估（中位）真实耗时估/实际
不注入6 秒25.3 秒0.26×
注入 79 tok/s15 秒25.3 秒0.59×
注入 159 tok/s（真值）10 秒25.0 秒0.40×
注入 254 tok/s13 秒26.4 秒0.49×
直接给秒数35 秒24.4 秒1.43×

Spearman(注入速率, 预估值) = -0.500，log-log 斜率 b = -0.158 （云端同一测量是 −0.033 / +0.043，等于「没用」）

第三步 · 让它回看自己刚写的东西

这次它能算准了

实验臂估/实际误差倍数对数误差跨轮相关(预估,真实耗时)
不注入0.40×2.52×0.923+1.000
注入稳定速率1.34×1.34×0.295+0.486
直接给秒数0.89×1.13×0.121+1.000

长度从 500 字拉到 3000 字， 真实耗时从 5.0 秒涨到 16.7 秒（3.4 倍）—— 它报出的数字跟着真实耗时一起动，才算「有感觉」，而不是喊一个常数。
误差倍数 = e^对数误差，就是旁白里说的「差 X 倍」； 「估/实际」是方向（小于 1 是低估）。
注意：不注入那栏的跨轮相关也是 +1.000 —— 真正的区分在误差量级这一列， 靠的是 2.5× → 1.3× → 1.1×，不是秩相关。

第四步 · 长思考状态

边写边报时间？它只是在编节拍

实验臂标记数轮内相关末标记/真实节拍斜率
不注入12 个+1.00011.3×15.8
注入稳定速率12 个+1.00016.4×22.3
注入速率 + 字符/token 换算12 个+1.00014.9×21.3

轮内相关全是 1.0，斜率却高达 15–22（理想是 1.0）： 标记是条完美等差数列，R² = 0.998 —— 比真实时间规律得多，是编的。
思维链占掉约 26% 的真实时间，而模型看不见自己想了多久。

第五步 · 怎么修

尺子要换算到「工作单元」上

实验臂末标记/真实节拍斜率截距
速率 + 每单元产出量0.81×1.21-5.3 秒
再补上思考阶段耗时2.88×3.91-13.4 秒

速率只告诉模型「我多快」，不告诉它「写到哪了」。 补一句「每写完一个小节大约产出 N 个 token」，模型只要会数小节， 就能自己推出来大概过了多久。

结论

速率是尺子，不是时钟

但尺子必须准。
云端 API 的速率 2.39× 波动，尺子本身就是坏的，量什么都不准；
本机稳态 1.15×，同一把尺子量出来的时间就有用了。

工程做法
给绝对量
已过秒数 / 剩余预算 / 截止时刻
确要用速率
先测稳
滑动窗口累计平均 + 报区间，并配明确待写量
完
